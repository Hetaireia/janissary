Issue 1: Here-string paste fragility (P0)
Symptom: Pasted here-strings (@'...'@) over ~40 lines fail intermittently. The closing '@ doesn't reach the terminal; $var never gets assigned; PowerShell treats continuation lines as new commands.

Observed failures: 7+ times on $partB, $chunk1, $content, and others.

Workaround: Use array syntax instead:

powershell
Add-Content -Path $path -Value @(
    'line 1',
    'line 2',
    'line 3'
) -Encoding UTF8
Each line is a discrete quoted string. If paste breaks, we see exactly where. This pattern has succeeded every time.

For multi-line Python: write with Add-Content or use the $py = @'...'@ pattern only for short (<20 line) scripts.

Issue 2: return doesn't halt pasted blocks (P0)
Symptom: An if ($cond) { throw "..."; return } guard fires, prints its message, but execution continues into the next lines of the same paste.

Why: In PowerShell interactive mode, return exits the current statement only. It does not abort the surrounding block.

Workaround: Use if/else blocks with the entire protected operation inside the else branch:

powershell
if (-not $allTrue) {
    "ABORT: structure incomplete - NOT committing"
} else {
    # entire commit block here
}
This has worked reliably since we adopted it.

Issue 3: 0xC0000005 access violations (P1)
Symptom: Intermittent crashes of native subprocesses:

python.exe tools/ascension.py → exit: -1073741819 (0xC0000005)

git push origin main → push exit: -1073741819

Diagnostic: No locks, no stuck processes, no state corruption. The crash is transient and non-reproducible.

Workaround: Retry. Every observed instance succeeded on second attempt.

Mitigation for Python: python.exe -X faulthandler -u tools/ascension.py — the flags stabilize the interpreter and turn silent crashes into tracebacks. Use for any critical script.

For git: just retry. If it fails twice in a row, close Docker Desktop to free memory.

Context: Documented in docs/TROUBLESHOOTING.md (M36 deliverable). Windows-specific, correlates with subprocess spawn under memory pressure.

Issue 7: dependent blocks execute after prior block aborts (P0)
Symptom: Block N prints ABORT and exits, but Block N+1 was in the same paste and
executes anyway, committing broken state. Observed during M37: Block 6 printed
"ABORT: M37 tests failed (1)" but Block 7 (the commit) then ran and committed
05a0ff2 with a broken test.

Why: The if/else guard prevents statement-level fall-through WITHIN a block. It
does not prevent the terminal from consuming the next pasted block. This is
Issue 2 (return does not halt pasted blocks) at the paste boundary rather than
the statement boundary.

Workaround: Never batch independent commits into one paste. Each mutating block
must re-verify its own preconditions at the top: for a commit block, run pytest
and throw if not green before git add; for a state-mark block, check HEAD is the
expected commit before touching state.

Adopted: all M38 blocks after part 1 include explicit precondition checks. See
M38 Blocks 5-fix, 8-retry, 10.

Issue 8: git diff --shortstat returns empty after rapid write (P2)
Symptom: After [System.IO.File]::WriteAllText($path, ...), git diff --shortstat
-- $path returned empty even though file content had changed. git add $path &&
git diff --cached --stat then correctly showed the diff.

Why: Windows NTFS mtime granularity plus git index stat cache. git diff on
unstaged changes short-circuits when index stat looks unchanged; git add forces
a full content compare.

Workaround: Do not use git diff --shortstat as a pre-add guard. Either run
git update-index --really-refresh first, then diff; or stage-then-check via
git add && git diff --cached --shortstat && git reset HEAD on oversize.

Adopted: M37 Block C used post-add diff --cached --stat for verification.

Issue 9: three-layer quote nesting - empty-string-in-f-string-in-PS-array (P1)
Symptom: Set-Content -Value @('... f"{x or ''}..."') collapses empty-string
quotes to just a single quote, producing f"{x or '}" which Python rejects as
unterminated string. Also applies to re.sub newline patterns and any Python
string containing a literal empty-string that has to survive a PS paste.

Workaround: Avoid the construct entirely. Use chr(10) for newlines, "" for
empty-string fallbacks, or .replace with a sentinel. If empty-string must
appear literally, use four single-quotes in the PS source.

Adopted: Block 4-fix-2 uses chr(10); Block 9a uses alternate payload_value.

Issue 12: idempotency guards on re-paste abort at git commit (P2, cosmetic)
Symptom: Re-pasting a write-verify-commit block after a prior successful run:
write guards correctly throw Already exists, but the trailing git commit still
fires and fails with nothing to commit, working tree clean, printing
ABORT: git commit failed. The abort is a false alarm - the state is correct.

Why: idempotency guards prevent re-writing files, but there is no guard on
git commit itself when nothing is staged.

Or accept that abort-at-commit after re-paste is a false alarm and cross-

Issue 3 refinement: 0xC0000005 can mask real errors AND mask successful runs (P1)
The observed 0xC0000005 crash of python.exe in this session masked two different
Python errors across two retries: (1) a real NameError from a missing import
(see Issue 10); (2) a pytest run that had actually completed 882 passed with
LASTEXITCODE 0 on retry, but a prior transient crash had returned non-zero with
no stdout, causing a false-positive test failure.

Lesson: do not trust LASTEXITCODE alone. Verify that the actual OUTPUT contains
the expected success marker, not just that exit code is zero.

Pattern: $out = (... 2>&1 | Out-String); if ($LASTEXITCODE -ne 0 -or $out
-notmatch "<N> passed") { throw }

Adopted: Block 8-retry, Block 9d, Block 10 all use this pattern.

Issue 13: PowerShell does not glob-expand command arguments (P2)
Symptom: `pytest tests/integration/test_sarif_*.py` fails because the
literal glob string reaches pytest unexpanded. Bash would expand it;
PowerShell passes arguments through verbatim unless the command itself
expands them.
Workaround: use `-k sarif` filter, `Get-ChildItem | ForEach-Object`, or
explicit file lists.

Issue 14: String.Replace() replaces ALL occurrences (P1)
Symptom: $raw.Replace($old, $new) replaced BOTH SessionSpec.headers()
and AuthConfig.headers() when they had identical bodies — silently
corrupting the first. Only surfaced at test time as AttributeError:
SessionSpec.headers() raised because it referenced .sessions, a field
only AuthConfig has.
Why: .NET String.Replace() is global, unlike Python str.replace(old,
new, 1) which takes an optional count.
Workaround: isolate the region first via Substring (between two known
anchors), use regex with scope anchor, or IndexOf + Substring. Never
trust .Replace() to hit only the intended instance when the target
block is generic.

Issue 21: docker ps 2>&1 yields ErrorRecord, not string (P2)

not [string]. .Trim() requires a string.
Fix: `Where-Object { $_ -is [string] -and $_.Trim() }`, or coerce with
