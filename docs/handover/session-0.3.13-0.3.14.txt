RELEASE RUNBOOK OPERATIONAL NOTES
=============================================================================

The 7.4.0 release took ~10 blocks and required workarounds for three
independent environment failures. All were infrastructure, not product.
Recorded here so 7.5.0's release is faster.

1. git push is broken on this Windows Dev build.
   - First push of the session (7862954..891341d) succeeded.
   - Every subsequent push: 0xC0000005 crash (gotcha O, new surface),
     or 3-consecutive 30s timeouts with stdin redirected to NUL (proving
     the hang is network, not a credential prompt).
   - Workaround for the tag: created via GitHub REST API (gh api
     repos/.../git/tags + gh api repos/.../git/refs), bypassing git.exe
     entirely.
   - Workaround for the release: gh release create <version> --target <sha>
     creates the tag server-side in the same API call. One operation,
     no push required.
   - When git push stabilizes, tag exists on remote AND local (both
     agree on 891341d).

2. gh auth login hijacks git's credential helper.
   - After `gh auth login`, git config credential.helper points at gh's
     git-credential shim, which blocks in non-interactive contexts.
   - The shim was the thing timing out push, not the network.
   - Fix: `git -c credential.helper= push <url-with-token>` bypasses the
     helper for a single command. Or restore credential.helper = manager
     for Windows Credential Manager.
   - Attempted: `git config --global --unset-all credential.helper` then
     `credential.helper manager`. This is now the standing config.

3. Standard Windows components are unavailable.
   - Test-NetConnection (NetTCPIP module) not found. Gotcha L surface
     expansion.
   - Use pure .NET instead: New-Object System.Net.Sockets.TcpClient
   - Confirms gotcha L family is not isolated to cmd.exe.

gh auth login hijacks credential.helper
   After `gh auth login`, git's credential.helper is set to gh's
   git-credential shim. The shim blocks in non-interactive contexts
   (scripts, Start-Process with redirected stdin), causing push to
   appear to hang. This is a frequent cause of "git push times out"
   on machines using gh CLI.
   Fix: `git config --global credential.helper manager` (uses Windows
   Credential Manager, no block). gh CLI operations still work; only
   git's credential flow changes.
