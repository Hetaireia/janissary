New gotchas
Gotcha AC — pre-commit pre-push hook crashes MSYS2 fork on this machine
  Symptom: git push hangs indefinitely. A timed git push --no-verify completes in seconds
  with a normal rejection, proving transport is healthy. The failing child shows
  "fork: retry: Resource temporarily unavailable" and 0xC0000005, same crash family as
  gh 2.101.0. Fix on this machine: rename .git/hooks/pre-push to pre-push.disabled.
  Do not re-enable without Defender exclusions or ASLR adjustment.

Gotcha AD — Deleting a tag ref converts its release to draft
  gh api --method DELETE .../git/refs/tags/<tag> flips the associated release to
  draft:true. Content is preserved. Recovery: one gh api --method PATCH .../releases/<id>
  with -F draft=false -F prerelease=false -f target_commitish=<full-sha>.

Gotcha AE — git/commits endpoint requires full 40-char SHA
  gh api .../git/commits/<short-sha> 404s. Use gh api .../commits/<short-sha> (the
  contents endpoint) for short-SHA lookups, or pass the full SHA.

Gotcha AF — gh api -f vs -F
  -f sends strings; -F sends typed values (booleans, numbers, and @file reads). Use
  -F draft=false, not -f draft=false. Use -F body=@path for large bodies.

Gotcha AG — ConvertFrom-Json mangles non-ASCII from gh api
  $r = gh api ... | ConvertFrom-Json decodes UTF-8 output as the legacy OEM codepage in
  this PowerShell config, so an em-dash appears as mojibake in $r.body. The bytes GitHub
  stored are correct. Verify non-ASCII via gh api ... --jq ..., never via ConvertFrom-Json.

Gotcha AH — Placeholder-in-guidance defect (process gotcha, not technical)
  Several commands this session were handed over with literal placeholders (<ID>,
  <full-sha>, <HANDOVER CONTENT...>) and the operator pasted them verbatim, producing
  clean 404/422 rejections and one bad commit. Rule: when providing commands to the
  operator, use literal values only. Never templates. If a script must embed content,
  embed the content inline in the script, not as a placeholder.

Gotcha AI — release-state.json is gitignored
  The release engine's state file is not tracked. Updating it is local-only; do not
  attempt to git add it (git will warn "paths are ignored"), and do not treat its
  staleness as a repo defect. If a future session sees a 7.4.0-era Version in
  release-state.json, update it on disk only.

Gotcha AJ — throw does not terminate a pasted interactive script
  In PowerShell 7, pasting a sequence of statements into the interactive prompt and
  hitting Enter on a line that throws will print Exception: and then CONTINUE with the
  next pasted statement. $ErrorActionPreference = 'Stop' does not help. The only reliable
  way to make throw abort the rest of a pasted script is to wrap the entire body in a
  script block scope: & { ... throw ... }. Use that pattern for any operator-facing
  destructive script.

Recovery pattern that worked in 0.3.17
- Isolate before you retry. --no-verify push isolated transport from the hook in one step.
  Without it, the natural next move was Defender exclusions, which would have been wrong.
- Assert the invariant, then mutate. Every tag / release mutation was preceded by a tree or
  SHA check. The tree-SHA match (2451abe0 == 2451abe0) was the load-bearing check before
  the force-push.
- Verify with the source of truth, not the writer. git ls-remote / gh api --jq beat
  $LASTEXITCODE and ConvertFrom-Json every time. ConvertFrom-Json produced the only
  false negative of the session; a bad placeholder produced the only bad commit.
- Do not spend a second session on the same diagnosis. Hook restoration (Defender/ASLR) is
  a separate maintenance item; the plain-push success criterion was met without it.
- Check the file you just wrote before committing. A 90-byte "handover" should have been
  caught by the size guard — the guard was correct, the execution model was wrong. Fixed
  by & {} wrapper (gotcha AJ) and by not using placeholders (gotcha AH).
