DECISIONS UNDER THE STANDING ORDER THIS SESSION
=============================================================================

D-1  SSRF payload scope reduced from ADR-012 D2's 8 to 5, with delta
     documented. The 3 deferred payloads (metadata_http, metadata_v6,
     file) cannot be detected via collaborator OOB — metadata endpoints
     return content in the response body (which the target sends to the
     user, not the collaborator), and file:// has no network round-trip
     for a collaborator to observe. Detecting those requires response-
     body inspection (a separate detection path). The 5 shipped (http,
     https, gopher, dict, dns_only) cover the standard blind-SSRF case,
     which is the majority of modern bug-bounty SSRF findings. The 8 D9
     tests still survive because none of them depend on the deferred
     payloads specifically.

D-2  Kept _ssrf_phase as a per-param post-payload phase (not a global
     phase after all params). Rationale: ADR-012 D3 called for the
     payloads to run per-param so the finding's param attribution is
     correct. Running all SSRF payloads after the full scan would lose
     param attribution.

D-3  Recovered from broken c03e2d1 (nested here-string truncated
     collaborator.py to 1 line and test_ssrf.py to 79 lines but with
     import failure). Full reset to b2f5b91 via `git reset --hard`,
     deleted stray files, confirmed 611 baseline, rewrote via Python
     writer pattern (Path.write_bytes with raw triple-quoted strings).
     c03e2d1 existed briefly on local only, was never pushed, is not in
     the current history. This is gotcha V (new) recorded below.

D-4  Fixed gate exit-code handling. The prior gate block threw on exit
     code 1 (real test failure) but retried on any other non-zero. That
     is wrong: pytest exit 2 is a collection error (import failure,
     syntax error), not a transient crash. The retry loop hid the broken
     c03e2d1 for 3 attempts before falling through with a misleading
     "[gate] clean; 615 passed" message. Fixed in this session's
     commit blocks: any non-zero exit other than 0xC0000005 throws
     immediately with the full pytest output. This is gotcha W (new).

D-5  Fixed 2 integration tests that had unrealistic mock behavior. The
     original test_scanner_ssrf_hit_http_emits_finding and test_scanner_
     ssrf_dns_only_emits_info used MagicMock with new_unique_id returning
     the same value for all 5 payloads and poll returning the same hit
     for every poll. That produced 5 findings (correct code behavior
     for a mock that reports every payload as hit) but the test asserted
     1. The fix: new_unique_id.side_effect = [f"jns-u{i}" for i in
     range(5)] (distinct uniq per payload) and poll.side_effect = lambda
     u: [hit] if u == "jns-u0" else [] (hit only on the matched uniq).
     This exercises attribution rather than masking it.

D-6  Accepted local-only commit accumulation. Every commit since
     891341d has timed out on push (gotcha U). Rather than fight it
     again, this session's 3 commits (plus this handover) are local.
     Release of 7.5.0 will use gh release create --target (proven for
     7.4.0) which bypasses git push entirely. Product work is unblocked
     by git push state.

D-7  Session naming: this is 0.3.15 alone, not combined with 0.3.13-0.3.14.
     The 0.3.13-0.3.14 combined handover already lives at b2f5b91 and
     covers 7.4.0 + ADR-012 design. This handover covers the SSRF
     implementation and 7.5.0 version stamp.

V. Nested here-strings silently truncate content. NEW this session.
   Observed in 0.3.15 Block A v1: the PowerShell block used
   `$ps1 = @'...'@` containing `$collabPy = @'...'@` (nested here-
   strings). PowerShell's outer here-string terminated at the FIRST
   inner `'@`, so everything after that point ran as top-level script
   commands and the file `collaborator.py` was written as 1 line
   (missing content), while `test_ssrf.py` came out at 79 lines but
   with an import error (CollaboratorClient not found). The commit
   `c03e2d1` was created with broken content; the gate's pytest call
   exited 2 (collection error) 3 times, was retried, and fell through
   to a misleading "[gate] clean; 615 passed" message.

   Standard: any block whose target content contains a here-string must
   use the Python-writer pattern:
     $py = @'...'@         (single-level PowerShell here-string)
     python C:\diag\x.py
   with the content inside as a Python raw triple-quoted string
   (r-prefixed triple-quoted string). Never nest PowerShell here-strings. This
   is the fourth time this class has cost a block across the arc
   (0.3.14 handover, twice in 0.3.13, now 0.3.15); if it fires again it
   will promote to Rule 15.

W. pytest exit code 2 is a collection error, not a crash. NEW this
   session.
   The prior gate block's pytest loop was:
     if ($code -eq 0 -and $pytestOut -match 'N passed') { ok }
     if ($code -ne -1073741819) { throw }   # <-- only threw on non-crash
   Exit codes: 0 = success, 1 = real test failure, 2 = collection error
   (import failure, syntax error, fixture load error), 3 = internal
   error. Only 0xC0000005 (-1073741819) is a transient crash that
   warrants retry. Every other non-zero is a real failure that must be
   surfaced immediately with the full pytest output.

   This was masked by the c03e2d1 failure: collection error (exit 2)
   was retried 3 times, "passed" the loop, and the commit was created
   against broken files. Fixed in this session's commit blocks: any
   non-zero exit other than -1073741819 throws with full output.

  4. Harden the gate so this specific class cannot silently pass again.
  5. Move forward without re-litigating.
