ENVIRONMENT GOTCHAS
=============================================================================

Session 0.3.5 gotchas A-J remain in force.
Session 0.3.6 gotchas K-2, M, N, O, P remain in force.
Session 0.3.7 gotcha Q (PS joins string arrays on interpolation)
remains in force. New this session:

R. PowerShell aliases override user-defined functions.
     `function CP(...) { ... }` does not shadow the built-in alias
     `CP` (which is `Copy-Item`). When called as `(CP $text $pat)`,
     PowerShell resolves the alias first, invoking `Copy-Item` with
     `(?m)^\+\s*stages` as a source path, which throws
     "Cannot find drive" (or similar) under EAP=Stop.

     Observed in session 0.3.8 Block 4: assertion helper function
     `CP` was shadowed by the alias, causing an unhandled abort at
     the first assertion in the loop.

     Standard: name helper functions with an approved verb prefix
     (`Get-`, `Test-`, `ConvertTo-`, etc.) or a non-alias name.
     `Get-PatternCount`, `Test-ContentMatch`, etc. Avoid short
     acronyms. Or run `Remove-Item Alias:CP` before defining the
     function, but the naming standard is more durable.

S. Windows CRLF breaks .NET regex `(?m)$` anchors.
     In .NET, `(?m)$` matches before `\n` only. On CRLF text, the
     `\r` sits between the last content character and the anchor,
     so `--all-files$` does not match `--all-files\r\n`.

     Observed in session 0.3.8 Block 3: L4 pattern
     `(?m)^(#\s+)pre-commit run --hook-stage push --all-files$`
     matched 0 times on the CRLF file the migrate-config produced
     from an originally-LF file.

     Standard: when matching with `^` or `$` anchors, normalize to
     LF first (`$text -replace "\`r\`n", "\`n"`), or use
     `(?m)^...#.*?` patterns without `$`. Restore the original
     line ending when writing back if the pre-state was CRLF; for
     LF-pre-state files, always write LF regardless of what a
     Windows tool produced in between.

T. Silent git commit non-zero exit.
     `git commit --no-verify ...` returned non-zero with no output
     to stdout or stderr, in session 0.3.8 Block 5. HEAD did not
     move, no lock was present, index was staged, config was
     correct. The exact same command succeeded on immediate retry
     (Block 6) with captured output showing normal success.

     Same class as gotcha N (transient subprocess failure). Not
     reproducible on demand.

     Standard: retry once. Capture with `git commit ... 2>&1 |
     Out-String` and print `$commitOut` so the next reader sees
     what git said, even on failure. The retry-once pattern
     documented in gotcha N applies.
