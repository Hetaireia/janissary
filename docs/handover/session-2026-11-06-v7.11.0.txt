## Discipline lessons -- five false-successes this session, all assistant-side

1. Issued git tag/push for a release whose content edits existed only as
   prose. Nothing was committed; git ls-remote was empty, so the false tag
   never published. But the tag was described as "damage" before that was
   verified. Rule: never issue commit/tag/push for content that hasn't
   been written and value-asserted first. A "nothing to commit" result
   when a commit was expected is a failure signal, not a clean pass.

2. Asserted readback on a needle constructed from memory that didn't match
   the actual write (Amendment 27 heading has a date between em-dashes).
   Rule: assert on the value the tool reports via repr() on raw bytes,
   not on a pattern-match I expect.

3. `git commit -m "<long string with ; -> ()>"` under PowerShell failed
   silently on native argument marshalling. Short -m succeeded; -F file
   succeeded with full message. Rule: ALL multi-word git messages go
   through -F <file>. No exceptions.

4. `git rev-parse v7.11.0^{commit}` under PowerShell parsed ^{...} as a
   subexpression and launched a child pwsh with -encodedCommand. Rule: no
   ^{} forms in PowerShell command position. Use git rev-list -n1 <ref>
   (clean) or grep for ^{} in git output.

5. Handover content referenced but not provided in-line; user pasted the
   literal placeholder, resulting in a 32-byte file. Rule: if instructing
   a write, provide the actual content in the instruction. No placeholders
   for content that must be committed.

Near-miss (operator-caught): proposed gate `$remoteTag -notmatch $h` would
have falsely failed any annotated-tag push, because the remote ref is the
tag object, not the commit. Same class as #2. Corrected approach:
verify peel via `git ls-remote origin | Select-String 'v7.11.0'` and check
that the second line (the ^{} line in the output) matches HEAD, or
cross-check `git rev-list -n1 <tag>` against HEAD.

## Environment gotchas added this session

- PowerShell 7.6.9 and 5.1 both mangle long -m args containing ; -> ()
  to native commands (git, gh). Use -F <file>.
- ^{commit}, ^{}, and similar brace forms become subexpressions in
  PowerShell. Never pass them as arguments. Grep for them in output instead.
- Pager can swallow `git show --stat` output in PS 7. Use `git --no-pager`
  or `--name-only` + count.
- pip editable-install metadata is STALE after pyproject.toml version bump.
  janissary.__version__ reads importlib.metadata, which reads the
  installed distribution, not pyproject. Refresh with `pip install -e .`
  on any dev machine after a version change. CI is unaffected (fresh
  install every run). This caused test_runtime_version_matches_pyproject
  to fail post-bump until refreshed.
- Windows git.exe flake: 0xC0000005 on git tag --list subprocess
  (test_pyproject_not_behind_newest_tag). Passes on retry. Linux CI
  unaffected. Recurred this session; also observed on
  `pre-commit install --hook-type pre-push` -- retry needed.
- .NET statics ([System.IO.File]::ReadAllBytes/ReadAllText) resolve
  relative paths against process CWD, not PowerShell's $PWD. Use absolute
  paths, or use Get-Content -Raw / Set-Content which respect PS provider.
- PS 7 may return exit code 130 (SIGINT) from `git commit` if the terminal
  receives an unexpected interrupt during pre-commit hook execution. Retry
  is safe if HEAD did not move; no commit landed.
