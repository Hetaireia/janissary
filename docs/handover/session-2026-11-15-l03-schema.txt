Change 4 — §4.4 full section replacement
  Old section (baselines.jsonl and reproducibility summary, ~20 lines) replaced with an expanded §4.4 carrying:
  - baselines.jsonl keyed by baseline_id = sha256(run_id|target|param)[0:16]; run and parameter part of identity so a baseline from one run is never silently reused for another. Blind oracle carries baseline_id: null.
  - Run identity and independence contract: distinct run_id, matching target and config_hash, baseline collection where applicable (quote oracle only; blind has no baseline), run completion recorded. A qualifying run counts regardless of whether every evidence boolean was collected.
  - Replay detection: replaying under a retained run_id produces no new qualifying run; existing runs_observed does not increment. A copied run directory assigned a fresh run_id is indistinguishable from a genuinely new run by the schema's mechanisms — independence is an assertion of the schema's rules, not a cryptographic proof of execution history.
  - config_hash: SHA-256 over canonicalised configuration dimensions (payload set, MIN_TIMING_DELTA / MIN_TIMING_Z / MIN_SLEEP_FLOOR / BAND_SLACK, oracle enablement flags, authentication config). Manifest carries config_hash, config_hash_algorithm, config_hash_inputs.
  - reproducibility_summary.jsonl: one record per composite identity (target, category, dialect, oracle, param, payload_pair), scoped to exactly one config_hash. summary_id = sha256(target|category|dialect|oracle|param|payload_pair|config_hash)[0:16]. run_id is NOT part of the key; the summary groups evidence across runs.
  - runs_observed = len(qualifying_runs), never derived from evidence-field population.
  - Per-evidence field carries: five-state state (confirmed-true, confirmed-false, disagreed, disagreed-within-run, unobserved), conditions array (not-probed, partial-observation, within-run-disagreement, cross-run-disagreement), partial flag, run_values as string values (never booleans), disagreement_runs, unobserved_runs, and four attempt counters (attempts_total, attempts_observed, attempts_true, attempts_false, attempts_unobserved).
  - Four-counter identities: attempts_total = attempts_observed + attempts_unobserved; attempts_observed = attempts_true + attempts_false.
  - Two kinds of unobserved distinguished: not-probed (attempts_total 0, attempts_unobserved 0) and probed-not-collected (attempts_total N > 0, attempts_unobserved N). Both produce run value "unobserved" and set partial: true; only the second sets the partial-observation condition.
  - No aggregate confirmed field. Per-field state is authoritative. summary_conditions is a reporting-level array (insufficient-runs, not-probed, partial-observation, within-run-disagreement, cross-run-disagreement) permitting coexisting conditions.
  - Authority and reading: consumer reads state, conditions, and summary_conditions together; "confirmed-false" with "insufficient-runs" is a negative observation from too few runs, not a settled result.

5. Operational lessons
================================================================================

Lesson 1 — Markdown triple-backtick sequences truncate the paste
  A here-string containing three consecutive backtick characters anywhere in its body can be truncated mid-paste by the terminal at that point, regardless of overall length. Observed twice this session: a ~2600-byte block with single backticks succeeded; a ~230-byte block containing a fenced code marker failed at the fence with Ctrl+C, leaving a partial continuation state.
  Remedy: avoid triple-backtick in source entirely (use 4-space indented blocks for multi-line code; single-backtick inline for short expressions), or construct the fence programmatically via $fence = ([string][char]0x60) * 3 and Add-Content -Value $fence. Every future multi-line Markdown write through this terminal should assume triple-backtick truncation.

Lesson 2 — wsl bash -c silent-return
  A wsl bash -c "cd ... && cmd1 && cmd2" chain with more than one output-producing command can return to prompt with zero output, no error, no visible exit code. Observed five times this session (pytest, git log, wc -l && sed, schema diff, WAF grep piped to head).
  Remedies:
  - One output-producing command per invocation.
  - Or redirect inside the WSL call: > /tmp/out.log 2>&1; cat /tmp/out.log — the ; separator is safe where && is not, and cat runs regardless of exit.
  - Environment-activation prefix (cd ... && source ... &&) is safe; it contains no output-producing commands.
  - grep piped to head through WSL has a specific variant: grep reports "ResourceUnavailable: Program 'grep.exe' failed to run: The pipe is being closed" after head closes the pipe. The output above the error is valid; the error is truncation, not failure.

Lesson 3 — Trust verification markers over line-count estimates
  Six arithmetic estimates this session were wrong (test counts, line counts, diff sizes). In every case marker-based verification passed. Line counts and diff-size predictions are estimates; marker checks and read-back comparison are the gate. When a block reports "all N markers pass" and "readback equals memory: True", the write is safe regardless of whether the line count matches the predicted value.
  Corollary: any handover number is only as good as its last verification. This session found four stale numeric or citation claims across inherited documents (1342 test count, 0.978 vs 0.977 F1, L01 evidence citation, tools/ascension.py existence). The register's citation convention (commit 9be8c5d) exists to prevent this class of drift; the handover corpus has no equivalent.
