§8 — Environment limitations (unchanged, plus TWO new)
Pre-commit still broken locally. CI remains enforcement path.

NEW: `code <new-path>` opens an unsaved buffer without creating the file.
If you then `git commit -F <file>` without saving, it fails with
"could not read log file '<file>': No such file or directory".
Always `New-Item -ItemType File -Path <file> -Force | Out-Null` before
`code <file>` when the file is new.

NEW: `gh run view <RUN_ID>` needs a real numeric ID. Copy from
`gh run list` output, not from a chat message placeholder. In PowerShell,
`<` is reserved (`<RUN_ID>` produces ParserError).

PowerShell 7 does not support bash heredocs. `<<'EOF'` fails with
ParserError. Commit via message file in repo directory:
  New-Item -ItemType File -Path 'commit-msg.txt' -Force | Out-Null
  code 'commit-msg.txt'    # paste, save
  Test-Path commit-msg.txt # must be True
  git commit -F commit-msg.txt
  Remove-Item commit-msg.txt

§9 — Session lessons (prior lessons still apply; new entries)
Bash syntax is not PowerShell syntax. Code goes into a file, opened by
`code <path>`, pasted from the copy button. Never drag-select a fenced
block from chat.

mmh3.__version__ does not exist. Use importlib.metadata.version("mmh3").
selectolax.__version__ works but is inconsistent — use importlib.metadata
uniformly.

ruff format is lazy-write: first --check reports "would reformat", first
format reports "files reformatted", second --check is clean. Trust the
second run.

Wheel probe: --platform manylinux2014_x86_64 with cp314 may silently
succeed with no output. Do not read empty output as "missing".

gh run watch picks runs without --workflow. Use
`gh run list --workflow=ci.yml --limit 3` then `gh run view <id>`.

git diff opens a pager. Use `git --no-pager diff`.

NEW: Lexbor's HTML5 parser auto-inserts html/head/body. Any parseable
HTML string produces shingle_count >= 1; shingle_count == 0 is only
reachable for empty/invalid input or after future changes to
extract_skeleton/SHINGLE_SIZE. Test such guards via monkeypatch.

NEW: When a test failure traces to a wrong test fixture (module is
correct), fix-forward with a targeted edit script rather than a revert.
Revert costs 2 extra commits and adds no safety over fix-forward when CI
is red only on the test step.

§11 — Phase 1.3c design decisions (unresolved)
1.3b's arming state is now available but not consumed. 1.3c wires the
discard half of ADR-002 §Combined signal requirement. Resolve before
coding; consider whether each needs an ADR-005 or a sub-amendment.

1. Finding-type scope of the discard path.
   Options:
     (a) Only CORROBORATOR_ONLY_TYPES (status_change, length_anomaly,
         length_shrink) — narrowest, targets Issue #1 directly.
     (b) All finding types with structural evidence — broader, risks
         losing TPs.
     (c) Only findings whose baseline is text-unstable
         (is_stable_body == False) — orthogonal signal.
   Recommendation: (a) AND (c). When the baseline is text-stable, the
   existing differential already discriminates; structural is redundant.
   When the baseline is text-unstable, the 39 SPA catch-all FPs occur —
   exactly the structural gate's target.

2. Root signature match semantics.
   ADR-002 §Combined signal says "matches the stored root signature".
   Literal SHA-256 equality, or allow any tolerance?
   Recommendation: exact equality. Root is one canonical hash; any
   tolerance reintroduces the churn the signature exists to reject.

3. Integration point in scanner.py.
   Options:
     (a) Post-process raw_findings from DifferentialAnalyzer.analyze()
         when arming.armed — filter before ScanFinding is constructed.
     (b) Filter at emission time (after ScanFinding).
     (c) Filter inside DifferentialAnalyzer (requires passing arming in).
   Recommendation: (a). Keeps the hook one-shot per payload response,
   makes the "gate transparent when unarmed" check trivially
   implementable as an identity function.

4. ScanSummary schema.
   Where does arming state surface?
     (a) Add "arming" key inside ScanSummary.baselines[param] (existing
         per-param dict).
     (b) New top-level ScanSummary.arming: dict[param, dict].
     (c) Don't surface; log only.
   Recommendation: (a). Keeps per-param metadata together; consumers
   already iterate baselines[param].

5. Discard observability.
   When the gate discards a finding, log at DEBUG, count in summary,
   both, or neither? Recommendation: both. A "discarded_count" per
   (param, reason) gives visibility without noise; DEBUG logs remain
   available for debugging.

6. Reproducing the 39 SPAs locally.
   Does the local benchmark image (janissary/owasp-benchmark:20cbf3d-
   ldapfix) include the SPA routes that produce the 39 catch-all FPs?
   Is there a synthetic SPA fixture in tests/integration/?
   Resolve before coding — the "0/39 FPs" success criterion from
   ADR-002 §Success criteria must be verifiable pre-merge.

7. Emit-path scope.
   ADR-002 §Combined signal has an "Emit:" clause (distance > 20 AND
   auxiliary signal). Is 1.3c supposed to ship both discard and emit,
   or only discard with emit deferred to 1.3d?
   Recommendation: discard only in 1.3c. 1.3d ships the emit half
   (already written into the roadmap). Confirms the phase boundaries
   ADR-004 §Consequences assumed.

8. Benchmark acceptance criteria for 1.3c.
