PROCESS RULES - AMENDED
=============================================================================

Rules 1-12 unchanged from session-0.3.6.

NEW Rule 13 (promoted from gotcha N by the "once = gotcha, three =
rule" standard): git subprocess output is unstable on this machine.
Every git informational command in a verification path must use
retry-on-empty with a cross-check. Never trust a single git subprocess
call to report state.

Three occurrences this arc that forced the promotion:
  1. 0.3.11: git status -sb returned empty output.
  2. 0.3.12 D1 v1: git rev-parse --short HEAD returned
     [System.Object[]] instead of a string.
  3. 0.3.12 D1 v4: git diff --cached --name-only returned 0 lines
     despite --stat showing 4 staged files.

Implementation pattern (Get-NonEmptyLines in commit scripts):
retry the git command up to 3 times, filter empty lines, cross-check
with the more reliable --stat form. Applied at preflight.

NEW Rule 14 (operational, this session's hard-won): commit-block
template. Every commit block must include:

  a. ruff check --fix .      (preprocessing, O-tolerant)
  b. ruff format .           (preprocessing, O-tolerant)
  c. ruff check .            (verify, O-retry on crash, exit-1 throws)
  d. ruff format --check .   (verify, O-retry on crash, exit-1 throws)
  e. pytest whole-tree       (3-attempt loop, exit-1 throws)

The verify steps only mean something after the preprocess steps have
normalized the tree. A "read-only verify" that skips the preprocess
will turn format drift into a false rule failure. This happened in
0.3.12 D2 v1 and cost one extra block.

Commit-message discipline (sub-rule of Rule 14): single quotes for
literals inside double-quoted -m; no backslash-escaped double quotes.
The pathspec failure from \"session\" is documented above under D-3.
