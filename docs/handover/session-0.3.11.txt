Decisions made under the standing order this session
-----------------------------------------------------
  D-1  Re-characterized the 0.3.10 next-scope item. "Agent-path 401
       detection (ADR-010 D6)" was framed as "just add the counter to
       the agent loop." Recon (agent/ file listing, full method map of
       agent.py and adapters.py, cmd_agent L800-1000) showed the actual
       concern is a process-global requests.Session monkey-patch at
       cli.py L877-890. The counter would have nowhere clean to hook.
       The item is properly a refactor-plus-feature, not a one-commit
       addition.

  D-2  Scoped ADR-011 to cover both the refactor and the detection.
       The alternative (splitting into two ADRs) would produce a small
       ADR for the refactor (which is not a design decision, just
       technical debt) and a small ADR for the detection. One ADR that
       names both, with the refactor as D1 and detection as D2-D5, keeps
       the design lock coherent.

  D-3  Committed to the two-commit split in 0.3.12: threading refactor
       (no new behavior, 603 existing tests still pass) then detection
       feature (6-7 new tests). The alternative (one combined commit)
       would be harder to review and harder to bisect if something
       regresses. Two commits: the larger refactor has a clean green
       foundation before the smaller feature lands on top.

  D-4  Chose response-hook over module-granular counter. The
       alternative (wrap each adapter call, increment a counter per
       module) is coarser: each adapter issues N requests, and a
       module that returns partial 401s would only count once. The
       session response hook fires per request, which matches ADR-010
       D3's per-response semantics. Threshold contract is shared
       across both ADRs; implementation is independent (session hook
       vs payload-loop counter).

  D-5  Corrected the gate-template from prior sessions. Sessions
       0.3.7 through 0.3.10 applied gotcha O tolerance only to
       `ruff check --fix`, not to `ruff format`. Session 0.3.11's
       opening gate crashed on `ruff format` (O-live, exit
       -1073741819) and the script's strict treatment of `ruff format`
       caused an abort. Both preprocessing steps are equally O-
       tolerant in the corrected template; only the verify steps
       (`ruff check .`, `ruff format --check .`) are the contract.
       Additionally, pytest now runs with a 3-attempt retry loop for
       O-class crashes (this session's opening gate also crashed
       pytest silently on the first retry, exit non-zero with no
       output). No new gotcha number; it is gotcha O applied fully.

without re-reconning. The session's second contribution is a
gate-template correction: gotcha O was applied inconsistently in
prior sessions - only `ruff check --fix` was O-tolerant, `ruff format`
was strict. This session's opening gate crashed on `ruff format`
