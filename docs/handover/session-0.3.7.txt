Q. PowerShell joins string arrays with spaces on interpolation.
     When "$arr" is used on a multi-line string array (e.g. output
     of `git diff` captured as $diff = git diff pyproject.toml),
     PowerShell concatenates lines with single spaces, destroying
     newlines. Regexes using (?m) with ^/$ anchors then match
     nothing because there are no line boundaries in the joined
     string.

     Observed in session 0.3.7 during item 1's commit block v2:

       $diff = git diff pyproject.toml 2>$null
       if ("$diff" -notmatch '(?m)^\+\s*"ruff==0\.16\.9",\s*$') {
           throw "diff missing 'ruff==0.16.9' pin line"
       }

     The diff DID contain the target line; the interpolation broke
     the ^/$ anchors. Cost one abort. Fixed in v3 by asserting
     against file content:

       $content = Get-Content pyproject.toml -Raw
       if ($content -notmatch '(?m)^\s*"ruff==0\.16\.9",\s*$') {
           throw "..."
       }

     Get-Content -Raw preserves newlines; string interpolation
     does not.

     Standard: assert against the thing that will be committed,
     not against a rendering of it. Use Get-Content -Raw (or
     Path.read_bytes().decode("utf-8") in Python) whenever line
     boundaries matter.

O-live. Gotcha O (0xC0000005 transient) confirmed live during item 2's
     gate at gate-run-20261027-184641.log:

       ruff check --fix .       -> exit=-1073741819 (0xC0000005)
       ruff format .            -> exit=0
       ruff check .             -> exit=0 ("All checks passed!")
       ruff format --check .    -> exit=0 ("114 files already formatted")

     The gate script logic is intentional: only the verify steps
     throw on non-zero exit; --fix is preprocessing. A crash on
     --fix followed by clean verify means the tree was already
     clean and the crash was transient. Do NOT alter the gate
     logic. If --fix crashes and verify PASSES, tree is clean;
     if --fix crashes and verify FAILS, throw fires and gotcha O
     retry applies. Both outcomes are correct.

N-reconfirm. During item 1's diagnostic step, a bare `git status -sb`
     via PowerShell returned empty output, while the `git diff`
     immediately before it (same subprocess invocation, same cwd,
     same env) succeeded. Transient. Consistent with gotcha N.
     No fix attempted; retry-once policy applies.
